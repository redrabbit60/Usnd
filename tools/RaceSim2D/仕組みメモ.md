# RaceSim2D 仕組みメモ（Unityデータ接続用）

`race_sim.html` がどういう仕組みで動いているかのメモ。
Unity側に入っているレースデータをこのツールに繋げる時に読む。

---

## 1. 全体構造

`race_sim.html` は1ファイル完結で、中身は大きく4ブロック。

```
race_sim.html
├─ <style>            画面レイアウト（CSS）
├─ <body>             ツールバー・canvas などのUI
└─ <script>
    ├─ SAMPLE_DATA          … サンプルJSONがそのまま埋め込んである定数
    ├─ データ管理            … validateAndPrepare() / positionAt()
    ├─ 描画                 … draw()（canvas 2Dに毎フレーム全描画）
    └─ 再生制御・読み込み    … requestAnimationFrame ループ、シーク、ファイル読込
```

外部依存ゼロ。ブラウザ標準の Canvas 2D API と FileReader だけで動く。

---

## 2. 入力データ形式（Unity側から出力してほしい形）

```json
{
  "distance": 2000,
  "horses": [
    {
      "id": 1,
      "name": "サンプルホース1",
      "laps": [
        { "point": 200, "time": 12.5 },
        { "point": 400, "time": 24.8 }
      ]
    }
  ]
}
```

| キー | 意味 | 制約・注意 |
| --- | --- | --- |
| `distance` | レース距離(m) | **1000〜3600の範囲チェックあり**。範囲外はエラー表示して読み込み拒否 |
| `horses[].id` | 馬番 | 表示色の決定にも使う（`(id-1) % 10` で10色パレットを引く） |
| `horses[].name` | 馬名 | ラベル表示のみ |
| `laps[].point` | スタートからの通過距離(m) | 昇順でなくてもOK（読み込み時にソートする） |
| `laps[].time` | スタートからの**累積秒** | 区間タイムではない点に注意 |

### Unity側データを変換する時のポイント

- `time` は「スタートからの累積秒」。Unity側が区間タイム（ラップ差分）で持っている場合は積算してから出す
- 刻み幅は200mでなくてもよい。**pointの間隔は任意**（100m刻みでも不等間隔でも動く）。
  むしろ点が細かいほど実況との照合精度が上がる
- 最終lapが `distance` に届いていない場合（例: 2000m戦でlapsが1800mまで）、
  直前区間の速度で**等速外挿**してゴール時刻を自動補完する（validateAndPrepare内）
- `(0m, 0秒)` の点は書かなくてよい。読み込み時に自動で先頭に追加される
- 馬は10頭想定（レーンは常に10本描画）。10頭未満でも動くが、11頭以上は10頭までしか描画されない

## 3. 位置計算の仕組み（コアロジック）

**「時刻 t に馬がコース上のどこ(m)にいるか」を毎フレーム計算しているだけ**。これが全て。

関数は `positionAt(horse, t)`：

1. 読み込み時に各馬の laps を `(0,0)` 起点の通過点リスト `pts` に変換しておく
2. 再生中の現在時刻 `curTime` に対し、`pts` を二分探索して「t を挟む2点」を見つける
3. その2点間を**線形補間**して位置(m)を返す

```
点A(800m, 48.5s) と 点B(1000m, 60.9s) の間で t=54.7s なら:
  r = (54.7 - 48.5) / (60.9 - 48.5) = 0.5
  位置 = 800 + (1000 - 800) × 0.5 = 900m
```

- `t <= 0` → 0m（ゲート内）
- `t >= ゴール時刻` → `distance` で固定（ゴール後は動かない）

つまり**物理シミュレーションは一切していない**。JSONの通過タイムを教師データとして
そのまま再生しているだけなので、Unity側のレース結果ログと同じタイムを入れれば
Unityと同じ進行が再現される（区間内は等速近似になる点だけ差が出る）。

## 4. 時間の進み方（再生制御）

- `requestAnimationFrame` ループで、フレーム間の実経過ミリ秒 × 再生速度を
  `curTime`（経過秒）に加算していく
- 一時停止 = 加算を止めるだけ。シークバー = `curTime` を直接書き換えるだけ
- レース総時間 `totalTime` = 全馬のゴール時刻の最大値。シークバーはこれを1000分割
- 画面のタイム表示は `curTime` そのまま。**実況音声の再生位置とこのタイムを揃えれば
  照合できる**（音声0秒 = レースの `curTime` 0秒 という前提）

⚠ 実況音声がスタートの何秒か前（ファンファーレ等）から始まる場合は、
その分のオフセットを頭の中で引くか、JSON側の time 全体にオフセットを足すこと。
現状ツールに音声オフセット機能はない。

## 5. 描画の仕組み

毎フレーム canvas を全消去して描き直す（差分更新なし）。

- **カメラ**: 最後方の馬〜先頭の馬が全部入る範囲＋余白を表示。最低400m幅。
  馬群が進むと表示範囲も横に流れる＝横スクロール
- **座標変換**: `x = (コース上のm位置 - 表示左端m) × (canvas幅 / 表示幅m)` の1行だけ
- レーンは上から馬1〜馬10で固定（縦位置は順位と無関係）
- 200mごとに破線マーカー＋「残り○m」表示、0mにSTART線、`distance` にGOAL線
- 順位ラベルは現在位置の降順（同位置＝ゴール後はゴールタイム順でタイブレーク）

## 6. データの入り口（Unityと繋ぐ場所）

読み込み経路は3つ。すべて最終的に `loadRace(jsonオブジェクト, ソース名)` に入る。

| 経路 | 実装 | 用途 |
| --- | --- | --- |
| ① 埋め込み `SAMPLE_DATA` | script冒頭の定数 | 起動時のデフォルト |
| ② ファイル選択 | `<input type="file">` + FileReader | **Unity出力のJSONを読む時はこれ** |
| ③ ドラッグ＆ドロップ | drop イベント + FileReader | 同上（手早い） |

`fetch()` を使っていないのは、ダブルクリック起動（`file://`）だと
ブラウザのセキュリティ制約で同フォルダのJSONすら読めないため。
**会社PCでもUnityからJSONをファイルに書き出し→②か③で読ませる、が基本フロー。**

### Unity側の出力例（C#）

Unityのレースデータから上記JSONを吐くだけでよい。イメージ：

```csharp
[Serializable] class Lap   { public int point; public float time; }
[Serializable] class Horse { public int id; public string name; public List<Lap> laps; }
[Serializable] class Race  { public int distance; public List<Horse> horses; }

// レース結果（各馬の通過点ごとの累積タイム）を詰めて…
File.WriteAllText("race.json", JsonUtility.ToJson(raceData), Encoding.UTF8);
```

※ 文字コードは **UTF-8** で出すこと（FileReaderがUTF-8で読む。馬名が化けたらここを疑う）。

### 常用データに差し替えたい場合

毎回ファイル選択が面倒なら、`race_sim.html` 内の `const SAMPLE_DATA = {...}` を
UnityからエクスポートしたJSONの中身で丸ごと置換すれば、開いた瞬間そのデータで動く。
構造さえ同じなら他の変更は不要。

## 7. 主要関数まとめ（改造時のあたり）

| 関数/変数 | 場所の目印 | 役割 |
| --- | --- | --- |
| `SAMPLE_DATA` | script冒頭 | 同梱データ。差し替えポイント |
| `validateAndPrepare(json)` | データ管理 | 検証・ソート・(0,0)追加・ゴール外挿・totalTime算出 |
| `positionAt(horse, t)` | データ管理 | **コア**。時刻→位置(m)の線形補間 |
| `draw()` | 描画 | canvas全描画。カメラ・レーン・マーカー・馬 |
| `frame(ts)` | 再生制御 | rAFループ。curTime を進めて draw() |
| `loadRace(json, name)` | 読み込み | 全読み込み経路の合流点 |
| `N_LANES` / `LANE_COLORS` | 描画の定数 | レーン数(10)・馬の色 |
